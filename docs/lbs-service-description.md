## 2. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | B-Territory |
| 서비스 형태 | 모바일 애플리케이션 (Android / iOS) |
| 주요 이용자 | 부산을 방문하는 외국인 관광객 |
| 서비스 개시(예정)일 | (실제 출시일 기재) |

부산의 관광지를 직접 방문하면 해당 지점을 점령하고, 이용자의 국적별로 구성된 팀이 부산의 각 구(區)를 두고 경쟁하는 위치기반 관광 게임 서비스입니다.

관광객이 실제로 관광지를 찾아가도록 유도해 부산 지역 관광을 활성화하는 것이 서비스의 목적입니다. 관광지 정보는 한국관광공사가 제공하는 공공 API(TourAPI)를 기반으로 구성합니다.

## 3. 주요 기능

**관광지 방문 인증 (점령)** — 이용자가 관광지 근처에 도착해 인증을 요청하면, 해당 시점의 위치가 관광지 반경 내인지 서버가 검증합니다. 검증에 성공하면 그 관광지가 이용자의 팀 소유로 기록됩니다.

**구역 점령 경쟁** — 한 구(區) 안의 관광지를 많이 점령한 팀이 해당 구를 차지합니다. 점령 현황은 지도 위에 팀별로 표시됩니다.

**팀 구성** — 이용자의 국적을 기준으로 팀이 자동 배정됩니다.

**실시간 이용자 매칭 (결투)** — 이용자가 앱을 사용하는 동안 서버가 인근에 있는 다른 팀 이용자를 탐지해, 미니게임으로 승부를 겨루는 결투를 신청할 수 있게 합니다. 이 기능은 이용자들의 상대적 거리를 실시간으로 판정해야 하므로 좌표를 일시적으로 보유합니다(4.4 참고).

**관광지 미션** — 관광지 인근에서 방문을 확인한 뒤 사진 촬영과 후기 작성을 제출할 수 있습니다. 방문 확인은 점령과 별개의 흐름이며 팀 점수에 반영되지 않습니다.

**지도 표시** — Google Maps SDK를 앱에 내장해 관광지 위치와 점령 현황을 표시합니다.

**부가 기능** — 팀별 순위, 명예의 전당, 같은 팀 이용자 간 실시간 채팅을 제공합니다.

## 4. 위치정보 이용 방식

### 4.1 수집하는 위치정보

| 구분 | 내용 |
|---|---|
| 수집 항목 | 이동통신단말장치의 GPS 좌표(위도·경도) |
| 수집 방법 | 이용자 단말의 위치 측위 기능 (앱 실행 중에 한함) |
| 수집 시점 | 앱이 화면에 표시되어 있는 동안에 한함 |

### 4.2 백그라운드 위치정보를 수집하지 않습니다

본 서비스는 **앱이 실행 중인 동안에만(포그라운드)** 위치정보를 이용합니다. 앱이 종료되거나 백그라운드로 전환되면 위치 수집이 즉시 중단됩니다. 단말 운영체제에 대해서도 포그라운드 위치 권한만 요청하며, 백그라운드 위치 권한은 요청하지 않습니다.

### 4.3 이용 목적

위치정보는 다음 세 가지 목적으로만 이용합니다.

1. **관광지 방문 인증(점령)** — 이용자가 관광지 반경 내에 실제로 있는지 확인하고 팀 점수에 반영
2. **실시간 이용자 매칭(결투)** — 인근에 있는 다른 팀 이용자를 탐지해 결투를 신청할 수 있게 함
3. **관광지 미션 이용을 위한 방문 확인** — 1호와 별개로, 미션 제출을 열기 위해 관광지 인근 여부만 확인

지도 화면 표시는 단말 안에서 이루어지며, 이용자의 좌표를 서버나 지도 사업자에게 전송하지 않습니다(6장 참고).

### 4.4 보유 및 이용기간

본 서비스는 **개인위치정보를 데이터베이스에 저장하지 않습니다.** 다만 위 4.3의 목적을 수행하기 위해 아래와 같이 **일시적으로 보유**합니다.

| 보유 대상 | 보유 형태 | 보유 기간 |
|---|---|---|
| 위치 좌표(위도·경도) | 서버 메모리(인메모리 저장소)에 **이용자별 최신 1건** | 앱 접속 종료 시 즉시 삭제. 비정상 종료로 남은 값은 마지막 갱신으로부터 **최대 15분** 이내 자동 삭제 |
| 미션 방문 확인 결과 | 좌표가 아닌 **관광지 식별자와 시군구 코드** | **24시간** 후 자동 삭제 |

좌표는 새 값을 받으면 이전 값을 덮어쓰므로 **이동 경로나 방문 이력으로 누적되지 않습니다.** 결투 성립 여부와 거리 판정을 위해 보유 중인 좌표를 참조하므로, "즉시 폐기"가 아니라 위 기간 동안 보유합니다. 계정을 삭제하면 두 가지 모두 즉시 삭제합니다.

인증 성공 시 데이터베이스에 저장되는 정보는 다음과 같으며, **좌표값은 포함되지 않습니다.**

| 저장 항목 | 내용 |
|---|---|
| 관광지 식별자 | 어느 관광지가 점령되었는지 |
| 팀 | 어느 국가 팀이 점령했는지 |
| 이용자 식별자 | 누가 점령했는지 |
| 점령 시각 | 언제 점령되었는지 |

즉 "누가 언제 어느 관광지를 점령했다"는 게임 기록만 데이터베이스에 남고, 이용자의 이동 경로나 위치 이력은 생성되지 않습니다.

### 4.5 이용·제공사실 확인자료

위치정보의 보호 및 이용 등에 관한 법률 제16조 제2항에 따라, 개인위치정보를 이용한 때마다 그 사실을 자동으로 기록하고 6개월간 보존합니다. 기록 항목과 구현은 `docs/compliance.md` 4장과 같습니다.

| 신고서 양식 요구 항목 | 값 |
|---|---|
| 대상 | 이용자 식별자 |
| 취득경로 | 이용자 단말의 GPS/네트워크 측위 (외부 위치정보사업자 경유 없음) |
| 제공서비스 | SVC-01 관광지 방문 인증(점령) / SVC-02 실시간 이용자 매칭(결투) |
| 제공받는자 | 없음 (제3자 제공을 하지 않음) |
| 이용일시 | 초 단위 이상 정밀도 |

이 기록에는 **좌표가 포함되지 않으며**, 계정을 삭제하더라도 법정 보존기간이 끝날 때까지 유지됩니다.

> 4.3의 3호(미션 방문 확인)는 현재 이 자동 기록의 대상이 아닙니다. 기록하도록 바꾸면 위 표에 SVC-03을 추가하는 변경신고가 필요합니다.

## 5. 위치정보 보호조치

**이용자 동의** — 회원가입 시 위치기반서비스 이용약관 전문을 앱 안에서 제시하고 동의를 받은 뒤에만 위치정보를 이용합니다. 서비스의 핵심 기능이 위치를 전제로 하므로 이 약관은 이용약관·개인정보처리방침과 함께 **가입 필수 동의 항목**이며, 동의하지 않으면 가입이 진행되지 않습니다. 동의한 문서의 종류와 개정일, 동의 일시는 원장에 기록해 보관합니다.

**동의 철회** — 이용자는 단말의 위치 권한을 해제하거나 계정을 삭제하는 방법으로 언제든 철회할 수 있습니다. 위치 권한을 해제하면 4.3의 서비스는 이용할 수 없으나, 순위 조회나 같은 팀 채팅 등 위치를 쓰지 않는 기능은 계속 이용할 수 있습니다.

**운영체제 권한** — 단말 운영체제의 위치 권한 요청 절차를 거치며, 이용자가 거부하면 위치정보를 일절 수집하지 않습니다. 포그라운드 권한만 요청하며 백그라운드 권한은 요청하지 않습니다(4.2).

**전송 구간 암호화** — 단말과 서버 간 모든 통신은 암호화된 연결(HTTPS/WSS)로 보호합니다. 실시간 좌표 전송은 WebSocket 구간을 사용하므로 두 프로토콜 모두 해당합니다.

**접근 통제** — 서버 접근은 인증된 관리자로 제한하며, 이용자 인증은 Firebase Authentication을 통해 처리합니다. 개인정보에 접근할 수 있는 권한은 업무상 필요한 최소한으로 제한합니다.

**최소 수집 원칙** — 서비스 제공에 필요한 최소한의 위치정보만, 필요한 시점에만 이용하며, 4.4의 기간이 지나면 자동으로 삭제합니다. 데이터베이스에 위치 이력으로 축적하지 않습니다.

## 6. 제3자 제공 및 위탁

**제3자 제공** — 개인위치정보를 제3자에게 제공하지 않습니다.

**지도 서비스** — 지도 화면 표시를 위해 Google Maps SDK를 앱에 내장해 이용하나, 이용자의 위치정보를 Google 측에 전달하지 않습니다. 지도 위의 현재 위치 표시도 SDK 기능이 아니라 앱이 직접 그립니다. 다만 지도를 그리는 과정에서 SDK가 Google과 통신합니다.

**처리 위탁** — 회원 인증은 Google(Firebase Authentication)에, 서버 운영은 Amazon Web Services에 위탁합니다. 두 수탁자 모두 개인위치정보(좌표)를 전달받지 않습니다.

## 7. 이용자 권리 보장

- 위치정보 이용에 대한 동의를 언제든지 철회할 수 있습니다. 단말의 위치 권한 해제 또는 계정 삭제로 철회할 수 있습니다.
- 위치정보 수집·이용에 대한 일시적 중지를 요구할 수 있습니다.
- 개인위치정보 이용·제공사실 확인자료(4.5)의 열람 또는 고지를 요구할 수 있으며, 오류가 있는 경우 정정을 요구할 수 있습니다. 요구는 아래 연락처로 접수합니다.
- 법정대리인의 동의가 필요한 만 14세 미만 아동은 가입을 제한합니다. 가입 시 만 14세 이상 여부를 확인하고 그 결과를 동의 이력으로 기록합니다.

## 작성 시 확인할 것

제출 전에 다음을 반드시 채우거나 검토하세요.

1. **괄호 표시된 항목 전부** — 상호, 대표자, 사업자등록번호, 소재지, 연락처, 출시일
2. **서비스 개시일** — 실제 앱 출시일 기준. 신고 기한(사업 개시 후 1개월)의 기산점입니다
3. **위치기반서비스 이용약관** — 5장에서 "약관 동의를 받는다"고 기술했으므로, 실제 약관이 앱에 준비되어 있어야 합니다. → 준비됨: `frontend/src/legal/location-terms.ts`, 가입 시 필수 동의 항목
4. **만 14세 미만 제한** — → 구현됨: 약관 시트의 만 14세 확인 체크박스와 서버의 `ageConfirmed` 필수 검증
5. **4.4의 보유 기간 수치** — "최대 15분"과 "24시간"은 코드 상수(`GEO_STALE_TTL`·`GEO_PRUNE_INTERVAL_MS`·`VISIT_WINDOW_SECONDS`)에서 나온 값입니다. 제출 전에 현재 값과 일치하는지 확인하세요
6. **4.5의 제공서비스 코드** — SVC-01·SVC-02가 `backend/src/location-logs/constants.ts`의 `LocationServiceCode`와 일치해야 합니다

## 나중에 변경신고가 필요한 시점

이 문서는 **위치정보를 데이터베이스에 이력으로 축적하지 않고, 목적 수행에 필요한 기간(최대 15분 / 24시간)만 일시 보유한다**는 점을 핵심으로 기술했습니다. 다음에 해당하면 사실관계가 달라지므로 변경신고와 약관 개정이 필요합니다.

- 백그라운드 위치 추적
- 위치 이력 저장이 필요한 기능
- 4.4의 보유 기간을 늘리는 변경 (`GEO_STALE_TTL`·`VISIT_WINDOW_SECONDS` 등)
- 위치정보를 이용하는 서비스의 추가 — 4.5의 SVC 코드가 늘어납니다. 현재 `missions.service.ts`의 체크인이 좌표를 이용하면서 자동 기록 대상이 아니라, 이를 기록하기로 하면 SVC-03 추가에 해당합니다
- 개인위치정보를 제3자에게 제공하거나 위치정보를 수탁자에게 전달하는 변경

> 미션 사진 업로드는 이미 구현돼 있습니다. 사진 원본이 메타데이터 제거 없이 저장되므로 촬영 기기가 기록한 위치 정보가 파일에 남을 수 있으나, 서비스가 이를 추출·이용하지 않으므로 이 문서가 다루는 개인위치정보에는 포함하지 않았습니다(개인정보처리방침 제4조 7호·위치기반서비스 이용약관 제4조 7호에 같은 취지로 명시). EXIF 제거를 구현하거나 사진의 위치 메타데이터를 서비스가 이용하기 시작하면 이 판단을 다시 볼 것.

관련 배경은 [필요 법적 문서 / 약관 정리](./compliance.md)를 참고하세요.
