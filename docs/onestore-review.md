# 원스토어 검수 반려 대응 (2026-09-15 접수)

상품 **B-territory(OA01008950)** 에 대해 원스토어가 세 건을 지적했다. 각 건의 요구사항과 대응 위치, 그리고 **코드로 끝나지 않는 부분(ONEconsole 작업)** 을 함께 남긴다. 재검증을 요청하기 전에 3장의 체크리스트를 순서대로 확인한다.

| # | 지적 | 성격 | 상태 |
|---|---|---|---|
| 1 | 접근권한(위치) 사전 고지·동의 절차 미구현 | 앱 코드 | 구현됨 — 1장 |
| 2 | 앱 연령등급 설문 재진행 및 재검증 요청 | ONEconsole 작업 | **미완 — 개발자 콘솔에서 직접 해야 한다.** 2장 |
| 3 | 채팅 기능 주의·제재 안내문구 미구현 | 앱 코드 | 구현됨 — 3장 |

## 1. 접근권한 사전 고지·동의 (정보통신망법 제22조의2)

- 원스토어 공지: <https://dev.onestore.net/devpoc/support/news/noticeView.omp?noticeId=29422>
- 방송미디어통신위원회 가이드: <https://kcc.go.kr/user.do?mode=view&page=A02030700&dc=&boardId=1099&cp=1&boardSeq=44582>

법이 요구하는 것은 "권한을 쓰기 전에 **항목·이유를 필수/선택으로 구분해 고지**하고 동의를 받으며, **철회 방법**을 안내하라"는 것이다. 권한 요청 자체는 OS 대화상자가 하지만, 그 **앞에** 고지가 와야 한다.

### 구현

| 요소 | 위치 |
|---|---|
| 고지 항목의 단일 소스(필수/선택 구분, 대응 매니페스트 권한) | `frontend/src/constants/app-permissions.ts` |
| 고지 화면 | `frontend/src/components/permissions/AppPermissionNotice.tsx` |
| 표시 문구(ko/en) | `frontend/src/i18n/locales/*.ts`의 `permissions` |
| 확인 여부 보관·구독 | `frontend/src/lib/permission-notice.ts` (AsyncStorage 키 `permission-notice`) |
| 화면 배치 | `frontend/src/app/_layout.tsx` — 앱 루트 오버레이 |
| **OS 권한 요청 차단** | `frontend/src/hooks/use-location.ts` — 확인 전에는 `requestForegroundPermissionsAsync`를 부르지 않는다 |

화면만으로 막지 않고 위치 훅까지 막은 이유가 이 대응의 핵심이다. **이미 로그인한 채로 앱을 업데이트한 이용자**는 고지 화면과 `LocationBroadcaster`가 같은 프레임에 함께 마운트되므로, 화면만 띄우면 고지문 **위로** OS 권한 팝업이 겹쳐 뜬다 — 반려 사유가 그대로 남는 상태다.

고지 내용을 고칠 때는 `PERMISSION_NOTICE_VERSION`(현재 `2026-09-15`)을 함께 올린다. 저장소에 남는 값이 이 버전이라, 올려야 이미 확인한 이용자에게도 다시 고지된다. **권한을 추가하면서 이 값을 그대로 두면 기존 이용자는 새 권한을 고지받지 못한 채 그 권한을 요청받는다** — 법이 막으려는 상황 그 자체다.

### 현재 요구하는 접근권한

| 구분 | 항목 | 매니페스트 | 이유 |
|---|---|---|---|
| 필수 | 위치 | `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` | 현재 있는 구역 판정, 관광지 미션 방문 확인, 근처 이용자와의 결투 매칭 |
| 선택 | 없음 | — | — |

백그라운드 위치·카메라는 선언하지 않는다. 일반권한인 `FOREGROUND_SERVICE` 선언은 남지만 위치 포그라운드 서비스는 사용하지 않는다. **저장소는 한 번 들어왔다가 제거한 경우다** — 앱이 요청한 적은 없지만 `expo-image`(Glide)와 전이 의존성 `expo-file-system`이 각자의 AndroidManifest에 `READ/WRITE_EXTERNAL_STORAGE`(`maxSdkVersion="32"`)를 선언해, 병합되면 **Android 12 이하 APK에 고지하지 않은 접근권한이 실린다.** 둘 다 실제로 쓰지 않으므로(앱 전용 디렉터리는 권한 없이 접근한다) `app.config.js`의 `blockedPermissions`로 최종 매니페스트에서 제거했다.


`SYSTEM_ALERT_WINDOW`도 `blockedPermissions`로 제거한다. 검증 APK에서 앱의 기본 매니페스트 선언이 배포 빌드에 남아 있는 것을 확인했다. 개발용 성능 모니터 등에 쓰이는 권한으로, 앱 내부 고지 화면·결투 모달에는 필요하지 않다.

> 이것이 손으로 관리할 수 없는 종류의 문제라는 점이 중요하다 — 권한은 우리가 적어서가 아니라 **자동링크된 라이브러리가 끌고 와서** 들어온다. 그래서 `frontend/src/__tests__/constants/app-permissions-manifest.test.ts`가 node_modules 및 생성된 앱의 main 매니페스트(존재할 때)를 훑어, 고지됐거나·차단됐거나·일반권한(INTERNET 등)이 아닌 항목이 하나라도 있으면 실패한다. 의존성을 추가하다 이 테스트가 깨지면 **고지 목록에 추가할지 차단할지**를 그 자리에서 정하면 된다.

### ONEconsole 상품정보에 등록할 권한 설명

공지는 마켓 상품 설명 하단에 노출될 **권한 설명 필드**도 함께 요구한다. 앱 화면과 다른 문구를 적으면 둘 중 하나는 거짓이 되므로, 아래를 그대로 붙여넣는다(출처는 위 `app-permissions.ts`와 `permissions` 문구다).

```
[필수적 접근권한]
· 위치(정확한 위치·대략적인 위치): 현재 있는 구역 판정, 관광지 미션 방문 확인,
  근처 이용자와의 결투 매칭에 사용합니다. 앱을 사용하는 중(포그라운드)에만
  수집하며 백그라운드에서는 수집하지 않습니다.

[선택적 접근권한]
· 현재 요청하는 선택적 접근권한이 없습니다.

필수적 접근권한을 허용하지 않으면 구역 점령·미션·결투 등 위치를 사용하는 기능을
이용할 수 없습니다. 허용한 접근권한은 단말기의 설정 > 애플리케이션 > B-territory >
권한에서 언제든지 다시 변경하거나 철회할 수 있습니다.
```

> 권한을 추가하는 의존성을 넣을 때는 `app-permissions.ts`, 이 문구, 그리고 ONEconsole 등록 내용 **셋을 함께** 고친다. 고지하지 않은 권한이 매니페스트에 들어가 있는 것이 이 반려의 실제 원인이다. 위 가드 테스트가 그 시점을 알려주지만, ONEconsole 등록 내용까지는 테스트가 닿지 못한다.

## 2. 앱 연령등급 재설정 (ONEconsole 작업 — 코드 아님)

원스토어 안내 그대로다. 저장소에서 할 수 있는 일이 없고, **개발자 콘솔에서 직접** 해야 한다.

1. ONEconsole > Apps > 상품현황 > 상세 > 공통정보 > 연령등급 > 앱연령등급(대한민국)
2. 서비스 기준에 맞게 등급 재설정 후 **저장** — 원스토어가 안내한 예상 등급은 **3+**
3. 바이너리 삭제 및 교체 후 재검증 요청

기준 문서: <https://onestore-dev.gitbook.io/dev/docs/apps/product/common-info/age-rating/onestorerating>

> 등급 설문에서 이 앱이 갈리는 지점은 **이용자 간 상호작용(팀 채팅)** 과 **위치 공유** 항목이다. 둘 다 "있음"으로 답해야 한다 — 채팅은 같은 국적 팀원 간 실시간 대화가 있고(`backend/src/chat/`), 위치는 결투 매칭에 쓰인다. 콘텐츠 자체(폭력·성적 표현 등)는 해당 없음이라 예상 등급이 3+로 안내된 것이다. 상호작용 항목을 "없음"으로 답하면 3번 지적(채팅 안내문구)과 앞뒤가 맞지 않아 다시 반려될 수 있다.

## 3. 채팅 이용자 보호 안내문구

- 원스토어 공지: <https://dev.onestore.net/devpoc/support/news/noticeView.omp?noticeId=29889>

요구는 두 가지다. **의무** — 채팅 기능 이용 시 주의·제재 안내문구 고지. **권장** — 차단·신고 기능(이미 구현돼 있다, `docs/community-policy.md`).

안내문구는 윤리(비방·욕설·음란·광고 제재)와 결제·개인정보 보호를 **한 문구에 모두** 담아야 한다. 현재 문구(`i18n`의 `chat.safetyNotice`):

> 비방·욕설·음란·광고 등 불건전 행위는 운영정책에 따라 제재 대상이며, 피해가 발생할 수 있으므로 결제정보·개인정보는 절대 타인에게 공개하지 마세요.

구현: `frontend/src/app/(main)/chat/index.tsx` 상단 고정 배너. 함께 표시하는 `chat.reportHint`("메시지를 길게 누르면 신고·차단할 수 있습니다")는 권장사항인 신고·차단이 롱프레스에만 있어 검수자 눈에 띄지 않는 문제를 겸해서 푼다.

공지는 고정 노출이 어려우면 스크롤링도 허용한다. 이 앱에서 목록의 `ListHeaderComponent` 대신 화면 상단 고정을 선택한 것은 안내를 지속적으로 보여주기 위해서다 — 헤더로 넣으면 대화가 쌓이는 즉시 스크롤 밖으로 밀려 사라진다. `frontend/src/__tests__/app/chat-safety-notice.test.tsx`가 메시지 30건을 쌓은 뒤에도 문구가 렌더 트리에 남아 있는지 본다. 실제 스크롤 후 가시성 및 키보드·큰 글꼴 설정의 가독성은 에뮬레이터에서 별도로 확인한다.

## 4. 재검증 요청 전 체크리스트

1. [ ] 새 바이너리에서 **첫 실행 시** 접근권한 안내가 뜨고, **확인을 누르기 전에는 OS 위치 권한 팝업이 뜨지 않는지** 실기기로 확인
2. [ ] 이미 로그인된 상태로 앱을 업데이트했을 때도 1번이 동일한지 확인(이 경로가 겹침이 나던 자리다)
3. [ ] 채팅 탭 진입 시 안내문구가 보이고, 대화를 여러 건 주고받아도 계속 보이는지 확인
4. [ ] 빌드된 APK의 실제 매니페스트 확인 — `aapt dump permissions <apk>` 또는 EAS 빌드 상세의 권한 목록에 **위치 두 개 외의 접근권한이 없는지**(특히 `READ/WRITE_EXTERNAL_STORAGE`와 `SYSTEM_ALERT_WINDOW`가 제거됐는지). `blockedPermissions`는 Gradle 매니페스트 병합 단계에서 적용되므로 바이너리로만 최종 확인된다
5. [ ] ONEconsole 상품정보의 **권한 설명** 필드를 1장의 문구로 갱신
6. [ ] ONEconsole 연령등급 설문 재진행 후 저장(2장)
7. [ ] 기존 바이너리 삭제 → 새 바이너리 업로드 → 재검증 요청
